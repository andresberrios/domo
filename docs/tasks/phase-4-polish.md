# Phase 4 — Polish

The end-of-v1 sweep. Aborts, keyboard shortcuts, dark mode, error/loading states, responsive layout, onboarding.

## 12. Polish

Split into two checkpoints. **Both halves landed.** First half:
visual-robustness + first-run. Second half: interaction (aborts,
shortcuts, responsive) — verified live on desktop + mobile viewports.

- [x] **Aborts everywhere (session, env operations, build)** — session abort: Phase 3 step 11. Build: `DomoBuildProgress` already had a Cancel button (AbortController + `cancelled` emit, wired in `AddProjectModal` + project page). Env provisioning: `DomoAddEnvModal` now has an explicit **Cancel** (aborts the `coast run` stream *and* `envs.delete`s the half-provisioned env) distinct from "Run in background" (detach, keep provisioning). Env start/stop/restart/checkout are short coastd RPCs with no mid-call cancel primitive — intentionally left as busy-spinner (a fake abort would mislead).
- [x] **Keyboard shortcuts** — Nuxt UI `defineShortcuts` (⌘ auto-maps to Ctrl off macOS). Global (`app.vue`): ⌘B toggle workspace panel, ⌘1/⌘2 Files/Git tab. Scoped: ⌘I focus chat prompt (`DomoChat`, `usingInput`), ⌘S save file (`f/[...path]`, preventDefaults browser save), ⌘↵ commit (`DomoGitChanges`). Kbd hints surfaced via `UTooltip :kbds` on the navbar / Save / Commit buttons + the commit textarea placeholder.
- [x] **Dark mode** — `UColorModeButton` in `DomoCenterNavbar`; **visually verified light + dark** (real screenshots + `getComputedStyle`: primary `UButton` is `oklch(...)`, surface flips slate↔white, toggle round-trips). App uses Nuxt UI semantic tokens (only intentional exception: `DomoTerminal` `bg-black`); `DomoCodeEditor`/`DomoDiffView` react to `useColorMode`. **Root-cause fix found here:** the Nuxt UI v4 CSS entry was missing project-wide (`app/assets/css/main.css` + `nuxt.config` `css`) so Tailwind never ran — the app had been **fully unstyled since Phase 0**, undetected because all prior verification used the Playwright a11y tree (identical with/without CSS). Added the entry; see CLAUDE.md gotcha. Visual/UI work must now be screenshot-verified, not a11y-only.
- [x] **Error states + loading skeletons** — `app/error.vue` (global, wrapped in `UApp`, Go-home/Try-again), `<NuxtErrorBoundary>` around `<NuxtPage>` (per-view crash → `DomoEmptyState` + Retry), `<NuxtLoadingIndicator>` for route transitions, reusable `DomoEmptyState`, `USkeleton` loading block on the env overview page, `UAlert` for env-action errors. Fixed a spurious `400 /procedures/envs/list` (project/env pages called it with an empty `projectId` on not-found URLs / before projects resolve) — now a guarded `.call()`.
- [x] **Responsive mobile layout** — framework-native, not class-hack hiding. The dashboard group is a non-wrapping flex row (no vertical stacking), so: **(1) Terminal is no longer a "bottom panel"** — it's a center route `…/e/:env/terminal`, a peer of chat (`s/:session`) and file (`f/:path`); `DomoBottomTerminal` + `bottomOpen` deleted, `DomoCenterNavbar` links to it. **(2) Workspace (right) panel**: `useBreakpoints(breakpointsTailwind)` mounts exactly one — inline resizable `UDashboardPanel` at ≥lg (persisted `rightOpen`), `USlideover` drawer at <lg (ephemeral `rightDrawerOpen`, **default closed** — a persisted desktop `rightOpen:true` must not auto-open a full-screen drawer over the chat). **(3) Left rail**: already a slideover on mobile (Nuxt UI `UDashboardSidebar` built-in + `UDashboardNavbar`'s auto `UDashboardSidebarToggle`). Added `@vueuse/nuxt` (+ `@vueuse/core` direct dep). Verified live at 1280 + 390 px: no horizontal overflow, both drawers open/close, no dialog stacking, chat/terminal render, 0 console errors.
- [x] **Empty / onboarding states** — `app/pages/index.vue` rewritten: first-run onboarding (`DomoEmptyState` + "Add a project" CTA opening the rail's modal via shared `leftRail:showAddProject`) when no projects; a project-picker grid when projects exist (removed the stale "Phase 1 will wire up…" placeholder). Project/env "not found" now render `DomoEmptyState` with a back action.
